## A. Must fix before real money moves (backend) — DONE 2026-09-19, verified against mock bank/Yandex

- [x] **A1 No balance check before the Yandex debit.** `CashoutOrchestrator.cs:163-172` posts −gross unconditionally; only the mock rejects overdrafts (`MockYandexFleetData.TryDebit`). Real Yandex accepts negative balances → any driver can cash out more than they earned. Fix: read the balance inside the saga and reject `amount > balance`.
- [x] **A2 Two concurrent requests both pay.** `CashoutOrchestrator.cs:112-130` has no per-driver lock; double-tap or two devices with different idempotency keys both pass the daily-limit check. Fix: `pg_advisory_xact_lock` per driver or a partial unique index allowing one in-flight cashout per driver.
- [x] **A3 Request cancellation can strand a cashout after the Yandex debit.** The HTTP `CancellationToken` flows into every `SaveChangesAsync` and the bank call (`CashoutOrchestrator.cs:161-207`); a dropped connection leaves `Processing` with `NextAttemptAt = null`, which no worker filter matches. Fix: switch to `CancellationToken.None` after the reserve insert; add a sweeper for stale `Processing` rows.
- [x] **A4 Demo seed runs in production.** `Program.cs:238` seeds 3 demo parks and `ops@swich.dev / swich2026!`, `levan@operator.local / operator1!` into any DB; `SeedData.cs` has no environment gate and logs the passwords. Fix: gate behind `IsDevelopment()`.
- [x] **A5 OTP code + phone logged in production.** `AuthController.cs:78` logs plaintext phone and the live code in every environment. Fix: `if (_env.IsDevelopment())`.
- [x] **A6 Pending bank order treated as paid after a lost response.** `CashoutOrchestrator.cs:381-386` and `BankSendHelper.cs:501-506` map lookup status `Pending` to success without `IsPending` → Completed, invoice issued, driver notified; a later TBC failure never reverses Yandex. Fix: `IsPending: lookup.Status == Pending`.
- [x] **A7 Ambiguous bank failure ends in a Yandex reversal.** `CashoutOrchestrator.cs:470-478` abandons after retries regardless of failure code; `BANK_EXCEPTION` with failed lookups may already have paid. Fix: ambiguous last error → ReviewRequired, not reversal.
- [x] **A8 Idempotency lookup is global.** `CashoutOrchestrator.cs:76-85` matches keys across drivers/parks; a reused key returns someone else's cashout. Concurrent same-key requests → unhandled unique violation (500). Fix: scope to park+driver; catch the unique violation.
- [x] **A9 Settlement stuck in Processing forever** if the worker dies before `BankTransferId` is stored (`SettlementService.cs:227-237`); no step retries it. Fix: treat old `Processing` + null transfer id as retryable via `settle:{id}` lookup.
- [x] **A10 One park failing aborts the whole nightly run** (`SettlementService.cs:84-92`, no per-park try/catch). Fix: catch per park, continue.
- [x] **A11 Bank calls are not audit-logged.** `IApiAuditLogger` is only used by the Yandex client; `TbcSoapClient.CallAsync` goes to ILogger only. Fix: write an `ApiCallRecord` per TBC call.
- [x] **A12 Rate limiter trusts `X-Forwarded-For` from anyone** (`Program.cs:222-228` clears KnownProxies) and there is no per-phone OTP cap → SMS flooding once a gateway is wired.
- [x] **A13 Phone normalisation differs** between admin onboarding (`AdminParksController.cs:1327`) and login (`AuthController.cs:291`); `599123456` without `+` hashes differently → silent login failure. Fix: one shared normaliser in Core.
- [x] **A14 Reconciliation flags every settlement transfer as `orphaned_bank_send`** (`ReconciliationWorker.cs:290-301` only matches cashout transfer ids).
- [x] **A15 Cross-park write:** `RemoveDriverCard` (`AdminParksController.cs:1307`) does not check the driver belongs to the park.
- [x] **A16 Fee editable by park_admin/operator** (backend gated; settings form D14 still to hide the input) (`AdminParksController.cs:1016`, and the settings form); contractually fixed at 0.50 and meant to be Swich-only.
- [x] **A17 Invoice legal copy is Model A.5** ("კომერციული შუამავალი Swich Solutions" — commercial intermediary) in `InvoiceGenerator.cs:213-216`; also labels the Yandex profile id as a driving-licence number (line 131/222).
